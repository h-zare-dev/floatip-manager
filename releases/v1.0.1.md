# floatip-manager v1.0.1

Stable patch release for Netplan-based Linux servers.

## Changes

- Fix a race that could trigger `ipv4: Address already assigned` during `floatip add` when `networkctl reload` raced with explicit `ip addr add`.
- Avoid reconfiguring the host interface on every add/delete: generate the persistent Netplan backend configuration and apply the precise managed /32 address changes to the live interface.
- Adopt an address already configured on the detected interface instead of issuing a duplicate add.
- Reject an existing address with an incompatible prefix instead of modifying it silently.
- Preserve auto-detection of the IPv4 default-route interface and separation of floating addresses from primary IP/DHCP.
- Support reproducible installation from a Git tag using `FLOATIP_REF`.
- Add `floatip --version`.

## Install this exact version

```bash
curl -fsSL https://raw.githubusercontent.com/h-zare-dev/floatip-manager/v1.0.1/install.sh | sudo env FLOATIP_REF=v1.0.1 bash
```

## Commands

```bash
sudo floatip add 203.0.113.10
sudo floatip del 203.0.113.10
sudo floatip show
floatip --version
```

The installer changes the command binary only. It does not add, delete, or reconfigure live network addresses during installation.

**Scope:** For secondary/floating IPv4s bound directly to the guest interface on an existing Netplan + systemd-networkd setup. It does not manage cloud-router/NAT-only floating IPs.
